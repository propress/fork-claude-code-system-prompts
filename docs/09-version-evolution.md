## 2. 关键里程碑版本

### v2.0.14 — 起点

最早的文件包括：
- `system-prompt-identity` — Claude Code 身份定义
- `system-prompt-doing-tasks-*` — 基础任务执行规则
- `github-app-installation-pr-description` — GitHub 集成模板

### v2.1.18 — 核心规则确立

一次性引入 26 个系统提示词片段，建立了：
- 工具使用策略体系（tool-usage-*）
- 输出风格规范（tone-and-style-*）
- 安全审查框架初版

### v2.1.53 — Bash 工具大拆分

将单一的 Bash 工具描述拆分为 **45+ 个原子化片段**：
- bash-sandbox-* （16 个沙箱规则）
- bash-git-*（4 个 Git 操作规则）
- bash-sleep-*（4 个 sleep 控制）
- bash-alternative-*（6 个替代方案指引）

**设计意义**：这次拆分体现了"原子化"设计哲学的极致——每条规则一个文件，可独立开关。

### v2.1.69 — 验证与技能系统

引入：
- `skill-create-verifier-skills` — 创建验证器技能
- `skill-verify-skill` — 代码变更验证（此后经历多次大改）

### v2.1.78 — SDK 参考数据批量注入

一次性引入 11 个 data-* 文件，覆盖：
- Python/TypeScript 的 Files API、Streaming、Tool Use、Message Batches 参考
- 建立了"技能调用 → 数据注入"的参考架构

### v2.1.83 — 多语言 API 参考

扩展 API 参考覆盖至 8 种编程语言（Python、TypeScript、Ruby、Go、Java、PHP、C#、cURL）。

### v2.1.88 — 团队协作 + 精简

**双向变化**：
- 新增：部分对话压缩、PowerShell 5.1 支持、Config 工具
- 精简：Verify Skill 大幅压缩（减少约 2/3 文本）
- Token 净变化：-1,627

### v2.1.89 — 安全防护大升级

**+3,986 tokens**——最大的单版本 token 增长：
- Buddy Mode（编程伙伴人格系统）
- MCP 工具结果截断处理
- 远程计划模式（ultraplan）
- 安全监控大幅扩展（不可逆操作、公共发布、容器挂载）
- 验证专家增加对抗性验证协议

### v2.1.90 — 双向用户意图框架

安全监控引入双向用户意图——用户意图既可授权也可约束，彻底重构了安全评估算法。

### v2.1.91 — Agent 设计模式

新增完整的 Agent 设计模式参考指南，覆盖工具设计、上下文管理、缓存策略。同时强化了记忆投毒防护。

### v2.1.92 — 最新版本

精简调整：
- 移除通用 Hook 评估器，替换为专用的 stop 条件评估器
- Write 工具加强"优先用 Edit"指导
- MCP 截断处理改为分块读取

## 3. 演进趋势

### 趋势一：安全机制持续强化

```
v2.1.18  安全审查框架初版
v2.1.69  验证技能系统
v2.1.88  验证技能大幅精简（删除冗余）
v2.1.89  对抗性验证协议、不可逆操作扩展
v2.1.90  双向用户意图框架
v2.1.91  记忆投毒防护
v2.1.92  专用 stop 条件评估器
```

安全相关文件的更新频率是其他类型文件的 **3-4 倍**。

### 趋势二：从粗粒度到原子化

```
早期：  单个 Bash 工具描述文件（1个）
v2.1.53：拆分为 45+ 个原子化片段
v2.1.88：精简冗余，保持原子但更紧凑
```

### 趋势三：先膨胀后精简

```
v2.1.69  Verify Skill 初版（详细）
v2.1.88  Verify Skill 精简 2/3（保留核心）
v2.1.89  再次扩展（增加对抗性验证）
v2.1.90  再次扩展（增加观察报告）
```

这表明提示词经历"添加 → 发现冗余 → 精简 → 发现不足 → 精准扩展"的生命周期。

### 趋势四：多智能体从可选到核心

```
v2.0.x   单智能体模式
v2.1.33  TeamDelete 工具出现
v2.1.38  队友工作流出现
v2.1.88  TeammateTool 完整团队管理
v2.1.91  团队通信强化
```

## 4. 各模块演进速度

| 模块 | 首次出现 | 最新更新 | 主要版本数 | 稳定性 |
|------|---------|---------|-----------|--------|
| System Prompts（核心规则） | v2.0.14 | v2.1.92 | 15+ | 中（频繁微调） |
| Tool Descriptions（Bash 系列） | v2.1.53 | v2.1.53 | 1 | 高（一次成型） |
| Tool Descriptions（其他） | v2.1.14 | v2.1.92 | 8+ | 中 |
| Skills | v2.1.69 | v2.1.91 | 6+ | 低（频繁重写） |
| Data（SDK 参考） | v2.1.78 | v2.1.83 | 3 | 高 |
| Security Monitor | v2.1.18 | v2.1.92 | 10+ | 很低（持续演进） |

**最不稳定的文件**（更新最频繁）：
1. `agent-prompt-security-monitor-*` — 几乎每个版本都更新
2. `skill-verify-skill` — 经历"详细→精简→再扩展"的完整生命周期
3. `agent-prompt-verification-specialist` — 持续增强对抗性验证

**最稳定的文件**（创建后几乎不变）：
1. `tool-description-bash-sandbox-*` — v2.1.53 一次成型
2. `data-session-memory-template` — v2.0.58 至今不变
3. `data-github-*` — 早期创建，很少更新

## 5. Token 预算变化

CHANGELOG 记录的 token 变化趋势：

| 版本 | Token 变化 | 原因 |
|------|-----------|------|
| v2.1.89 | +3,986 | 安全大升级 + 新模式 |
| v2.1.91 | +2,043 | Agent 设计模式 |
| v2.1.90 | +815 | 安全框架增强 |
| v2.1.88 | -1,627 | Verify Skill 精简 |
| v2.1.92 | -167 | 移除冗余工具 |

整体趋势：**净增长**，但伴随周期性精简。安全和功能扩展带来 token 增长，而提示词工程优化（更简洁的表达、移除冗余）部分抵消增长。

## 总结

Claude Code 提示词系统的演进遵循一个清晰的模式：

1. **基础设施先行**（v2.0.x）—— 建立基本身份和规则
2. **原子化拆分**（v2.1.53）—— 大规模重构为细粒度片段
3. **功能扩展**（v2.1.69–v2.1.83）—— 验证、技能、SDK 参考
4. **安全持续强化**（v2.1.88–v2.1.92）—— 对抗性验证、双向意图、记忆防护
5. **团队协作成熟**（v2.1.88+）—— 完整的多智能体协作框架

这一演进路径反映了一个从**"能用"到"安全可靠"再到"协作高效"**的工程化成长过程。
